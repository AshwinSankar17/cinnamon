# Cluster Brain — mobile

Expo SDK 57 + TypeScript + expo-router app that pairs with a Brain on your cluster and lets you
watch threads, decide approvals, and stop/cancel work from the phone. It implements
`../protocol/API.md` (v0.2) and follows the STYLE-V2 "editorial light" look.

## Run it

```bash
cd mobile
npm install
npx expo start            # Metro dev server
npm run typecheck         # npx tsc --noEmit
```

The app uses native modules (camera, secure store, SQLite, notifications). Everything except
remote push works in Expo Go. For push, and for anything you'd ship, use a development build:

```bash
npx expo run:android                       # local build; needs Android SDK + a device or emulator
# or, in the cloud:
npx eas-cli@latest build --profile development --platform android
```

`eas.json` has `development` (dev client, internal APK), `preview` and `production` profiles.
`android/` and `ios/` are generated by prebuild (Continuous Native Generation). Do not commit or hand-edit them.

## FCM (push)

1. In Firebase, create a project and add an Android app with package **`dev.clusterbrain.mobile`**
   (placeholder id, set in `app.json`; change it before you create the Firebase app if you want another).
2. Download `google-services.json` and put it at **`mobile/google-services.json`**, next to
   `app.json`. It is gitignored. `app.config.ts` adds it to the Android config only when the file
   exists, so the app still runs without Firebase.
   On EAS, upload it as a *file* environment variable named `GOOGLE_SERVICES_JSON` instead.
3. Rebuild the dev client (`npx expo run:android` or `eas build`); config changes need a new native build.
4. Brain needs a Firebase service account to send FCM HTTP v1 messages to the token the app
   registers at `POST /v1/devices/push-token`.

The app creates the six Android channels from API.md (`needs_you` high + sound, `failed` high,
`done` default, `budget` default, `changed` low, `transport` min/silent). Brain must set
`android.notification.channel_id` to one of those ids.

## Layout

```

  pair.tsx               scan QR / paste JSON / type code, pin brain_pub, pair, verify brain_sig, push opt-in
  (tabs)/_layout.tsx     Inbox · Threads · Runs · Repos (redirects to /pair when unpaired)
  (tabs)/index.tsx       Inbox: "since you left" prose, Needs you, Running, Done, Pause/Resume
  (tabs)/threads.tsx     search, state + provider chips, pinned on top, grouped by repo, long-press sheet
  (tabs)/runs.tsx        GET /v1/jobs, cancel
  (tabs)/repos.tsx       GET /v1/repos
  thread/[id].tsx        coding chat: turns, steps, diffs, terminal output, jobs, approvals, composer
  approval/[id].tsx      decision summary, pending since, Deny (+note) / hold to Allow, signed
components/              ui primitives, Icon (SVG from the mockups), ConnectionBanner, ThreadActionsSheet, chat blocks
src/
  theme.ts               STYLE-V2 tokens and type ramp (the only place colours are defined)
  crypto.ts              device Ed25519 key, pairing transcript/HMAC, challenge/token/decision/endpoint sigs
  api.ts                 typed REST client, session handshake, refresh-on-401, Idempotency-Key
  ws.ts                  foreground-only WebSocket, subscribe/after_seq, 30 s ping, 1→60 s jittered backoff
  store.ts               expo-sqlite mirror: threads, events (thread_id, seq PK), meta
  push.ts                channels, native FCM token, tap routing, verified transport updates
  turns.ts               folds the event log into turns/blocks; unified-diff parser
  connection.ts          honest connection state (offline / unreachable / identity mismatch / revoked / paused / live)
```

## Protocol encoding (must match Brain byte-for-byte)

Documented at the top of `src/crypto.ts`. In short: `‖` is raw concatenation with no separators;
tags and strings are UTF-8; `brain_pub`/`device_pub` are raw 32-byte keys; `nonce_device`, the
challenge `nonce` and the pairing `secret` are base64url-decoded to bytes; everything binary goes
on the wire as base64url without padding. `host` in the challenge is the lower-cased authority of
the endpoint with `:443`/`:80` removed (what the HTTP stack sends as `Host`). `endpoint` is used
exactly as it appears in the pairing payload. The helpers were cross-checked against an independent
Node implementation (node:crypto + tweetnacl) for transcript, MAC and all four signatures.

Keys and tokens live in expo-secure-store (`AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY`). The device key is
a 32-byte Ed25519 seed that never leaves the phone.

## Stubbed or not yet working

- **Not run on a device.** Typecheck passes and the Android JS bundle builds (`expo export`); no
  native build or device run has been done, and nothing has been tested against a real Brain.
- **Type-code pairing needs the secret.** API v0.2's MAC uses the 32-byte `secret`, which only the
  QR/JSON carries. "Type code" therefore also asks for the secret and pins `brain_pub` from
  `/v1/health` after you confirm the fingerprint (explicit trust on first use). Code-only pairing needs a protocol change (PAKE or a code-derived key).
- **No `GET /v1/approvals/{id}`** in v0.2. The approval screen finds the approval in `/v1/pending`;
  an approval that is already decided shows "no longer pending" rather than its outcome.
- **Transport push `ts`.** `endpoint_sig` covers a `ts` that the push `data` schema does not list.
  The app reads `data.ts` and ignores the push if it is missing.
- **Lists poll.** The WebSocket is per-thread, so Inbox (20 s), Threads and Runs (30 s) poll while focused.
- **Shapes API.md leaves open.** `Repo`, `since` and `waits` are typed loosely. Waits are not shown
  in the Inbox yet. `assistant.text` events render as separate paragraphs (not streamed deltas).
- **Not built yet:** new-thread sheet, Select/bulk actions, turn detail, Changes/FileDiff screens,
  run detail, cluster sheet, settings, rules, A/B listen, audio playback, attachments, voice input,
  copy/undo/retry turn actions, provider switch from the composer.
- **iOS push:** `getDevicePushTokenAsync` returns an APNs token on iOS; Brain's FCM sender cannot use it as-is.
- Web is not a target. `react-native-web` and `react-dom` are left over from the template.
